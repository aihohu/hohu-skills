# 维护文档

修改安装步骤、工作流或辅助脚本后，按本页选择更新位置，并检查读者能否按文档完成操作。通用要求见 [HoHu 文档维护规则](https://github.com/aihohu/hohu-admin/blob/main/docs/DOCUMENTATION.md)。

## 选择更新位置

| 改动 | 更新位置 |
| --- | --- |
| 项目定位、快速开始、文档入口 | 根目录的两份 README |
| 在线安装、应用使用、业务开发教程 | [HoHu 文档站](https://hohu.org/zh/guide/cli/skills) |
| 本地源码安装与排错 | [installation.md](installation.md) |
| 工作流边界、项目检查器和安装器契约 | [workflows.md](workflows.md) |
| 贡献者检查命令和验收方法 | [validation.md](validation.md) |
| Agent 执行步骤和参考资料 | 对应的 `skills/<name>/` 目录 |
| 影响兼容性或维护方式的长期决策 | `docs/adr/` |

同一主题保留一份正文，其他位置链接到它。草案、计划、截图和一次性验收记录放在被忽略的 `.local/`；将需要长期保留的操作方法整理成手册，将设计取舍整理成 ADR。需要协作评审的提案通过 Issue 或 PR 分享。

## 更新与检查

1. 对照当前脚本和工作流核对前提、参数、执行目录、预期结果及失败后的处理方式。
2. 修改快速开始时同步两份 README；修改文档站页面时遵守站点的双语检查流程。
3. 新增或重命名文档后更新[文档索引](README.md)、[公开文档清单](public-docs.txt)及所有引用。清单使用仓库根目录相对路径。
4. 检查清单中文件存在，仓库内链接和锚点有效，公开页面没有引用本地过程资料。示例使用占位路径和测试数据，不包含真实凭据。
5. 在仓库根目录执行 `git diff --check`；暂存后用 `git diff --cached` 确认提交范围和内容。

文档清单、链接与内容目前由贡献者检查；CI 中的辅助脚本测试和 Ruff 不包含这些检查。仅修改文档时，无需重新运行数据库或真实模型验收；若同时改变可执行行为，继续按[验证指南](validation.md)运行相关检查。
