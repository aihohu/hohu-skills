# 文档维护与公开范围

HoHu Skills 的公开文档服务于使用者和贡献者。按读者要完成的任务组织正文，先给出可执行步骤和预期结果，在相关位置解释限制。代码注释与文档字符串使用英文，正式维护说明以中文为主。

## 正文归属

| 位置 | 内容 |
| --- | --- |
| 双语 README | 项目定位、能力、快速开始、文档和贡献入口 |
| 本仓库 docs | 安装器与检查器说明、维护验证要求、长期架构决策 |
| skills | 编程助手执行的英文工作流及按需读取的参考资料 |
| hohu-admin-docs | HoHu 使用、部署及业务开发教程 |
| 被忽略的 .local | 草案、计划、调试记录、截图、一次性验收报告 |

同一主题只有一个维护来源，其他位置使用链接。README 保留简洁起步路径，详细参数和排错集中在安装说明。跨项目规范遵循 [HoHu 文档维护规则](https://github.com/aihohu/hohu-admin/blob/main/docs/DOCUMENTATION.md)，框架契约由目标版本的源码与正式规范维护。

## 内容要求

- 说明适用读者、前提、操作和成功结果，命令须能与仓库代码对应。
- 介绍已实现能力，不用通用“开发版本”横幅、占位章节或尚未交付的承诺填充页面。
- 必要限制放在相关步骤，避免让读者自行从源码寻找基本操作答案。
- 双语 README 的能力、命令、链接用途和限制同步更新。
- 精确源码兼容清单统一维护在 Skill 中，正式文档不复制多份提交列表。
- 示例不包含本机工作区路径、真实凭据、测试账号或业务数据。

## 设计与过程资料

Spec-First 继续适用：先形成设计，再实现，再回写稳定行为。原始草案和 Plan 状态保存在本地设计记录，公开手册不作为进度日志。长期决策使用 ADR，说明原因、反例和回归依据。

本地目录不能成为团队唯一知识库。需要协作的提案通过 Issue/PR 或团队渠道共享，必要的安全边界和贡献知识继续公开。Git 忽略不是保密机制，也不会移除已有历史。

## 文档检查

新增正式 Markdown 文件时，同步更新[文档索引](README.md)及 [public-docs.txt](public-docs.txt)；清单采用仓库根目录相对路径，包含 README、贡献说明、代理指令和随安装包分发的 Skill 文档。

提交前检查：

1. 清单中的文件均存在，仓库正式 Markdown 无遗漏。
2. 仓库内链接和锚点可解析；正式文档不链接本地过程资料。
3. 双语 README 的步骤一致，命令参数与当前脚本匹配。
4. 暂存内容不含本地产物，`git diff --check` 通过。

当前 CI 执行辅助脚本测试、覆盖率及 Ruff；文档清单和内容评审是贡献者提交前检查，不宣称已有自动文档门禁。链接检查只能证明结构有效，不能替代操作路径和内容评审。
